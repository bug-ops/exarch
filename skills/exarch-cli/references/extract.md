# extract: full flag reference

`exarch extract <ARCHIVE> [OUTPUT_DIR]`. Always pass `OUTPUT_DIR` (default is the CWD). Common flags are in `SKILL.md`; this file holds the rest and the edge cases.

## Quotas and limits

| Flag | Default | Notes |
|---|---|---|
| `--max-files` | 10000 | Counts every entry once in every format and command: directories, links, and entries skipped by a selection or `--allowed-extensions`. `QuotaExceeded` past it. `0` refused. |
| `--max-total-size` | 500 MiB | Cumulative extracted size; suffixes `K/M/G/T`, either case. `0` refused. |
| `--max-file-size` | 50 MiB | Single file; same syntax. `0` refused. |
| `--max-compression-ratio` | 100 | Uncompressed/compressed ratio. Applies to ZIP and non-solid 7z. Fractions allowed (`2.5`); `0`, negative, and non-finite refused as `InvalidConfiguration` (setting `max_compression_ratio`). Also on `list`/`verify`. |
| `--max-path-depth` | 32 | Components per entry. `0` refused. An entry name over the host length limit fails with `I/O error: file name too long`. |
| `--parallel-decode-memory <SIZE\|off>` | 128M | 7z only: memory for decoding LZMA2 runs ahead on worker threads. `off` = one thread; `0` refused. |

Notes on the ratio:
- Solid 7z blocks are not ratio-checked per entry; with `--allow-solid-archives` each block is checked as a whole against a fixed 1000x limit (Rust API only).
- An entry with declared data but zero compressed bytes is always a `ZipBomb` (ratio `unbounded`); its hint says the size metadata is inconsistent.
- For a compressed TAR, entries left undecoded by `--allowed-extensions` or duplicate skipping are bounded too: past `--max-file-size` and `--max-total-size`, skipped data may decode to at most ratio x the compressed input read so far, else `ZipBomb` with scope `skipped entries`. Raise `--max-compression-ratio` for such a case.

## Policy flags

| Flag | Default | Notes |
|---|---|---|
| `--preserve-permissions` | off | setuid/setgid stripped regardless. |
| `--allow-symlinks` | off | Accept symlinks that resolve inside the destination. Link targets with unresolvable `..` are always rejected. `extract` never writes through a symlink already below the destination: by default `path component is a symlink: <path>` (`SecurityViolation`, `relaxable_by` `symlinks`); with the flag a pre-existing link is accepted only if it resolves to a directory inside the destination. One that leaves the destination fails `SymlinkEscape`; a dangling, looping, or file-pointing one fails `refusing to create <entry> under the existing symlink at <parent>` (not relaxable). A symlinked destination root is accepted. |
| `--allow-hardlinks` | off | Hardlinks resolving inside the destination. |
| `--allow-absolute-paths` | off | For ZIP the leading root and any drive/UNC/verbatim/device prefix is stripped (`/tmp/x` lands at `<dest>/tmp/x`). |
| `--allow-world-writable` | off | Allow mode `0o002`. |
| `--allow-solid-archives` | off | Solid 7z (memory-exhaustion vector; trusted archives only). |
| `--zip-consistency <enforce\|ignore>` | enforce | ZIP only. `ignore` keeps the central-directory view and raises no structural finding; use only for trusted producers. See [formats.md](formats.md). |
| `--decode-reuse <off\|memory\|temp-file>` | memory | ZIP only. Where the structural check keeps decoded deflate/bzip2/zstd output so extraction does not decode twice. `memory` keeps up to 256 MiB in RAM, `temp-file` up to 256 MiB in an unnamed temp file (plaintext in the temp dir until the run ends), `off` keeps nothing. No effect under `--zip-consistency ignore`. Invalid value: exit `2`. |
| `--mark-propagation <never\|when-marked>` | never | Copy the archive file's download-origin mark onto extracted files; see "Download mark". Invalid value: exit `2`. |
| `--banned-component <C>` | `.git .ssh .gnupg .aws .kube .docker .env` | Replaces the default list. Repeatable and comma-separable; tokens trimmed. A token with `/` or `\`, or equal to `.`/`..`, or a non-empty value with no token (`,`) is an error. |
| `--allowed-extensions <EXT>` | all | Regular files only. Repeatable or comma-separated; leading dot optional, case-insensitive. A value that can never match (`tar.gz`, `a/b`) or names no extension (`,`, `""`) is an error. Order of checks: path first, then allowlist, then quotas: a skipped file is not charged to size quotas, creates no directories, and counts in `files_skipped`. A skipped entry with an unsafe path is refused, not skipped. |

## Selection: `--include`, `--exclude`, `--strip-components`, `--flatten`

All four also exist on `list` and `verify`.

- `--include <GLOB>` / `--exclude <GLOB>`: repeatable; exclude is applied after include and wins. Same grammar as `create --exclude` ([create.md](create.md)); a match also selects everything below it. Quote patterns. Patterns match the entry path as `list` shows it, before stripping; a leading `./` is not a component.
- `*` and `?` never cross `/`, and a pattern without `/` matches at any depth (unlike bsdtar, which anchors at the archive root).
- An `--include` that matches no entry is an error after the scan (`InvalidConfiguration`, setting `entry_include`); nothing is kept under `--atomic` or for a TAR into a new destination, while a non-atomic ZIP or an existing destination keeps what was written earlier. An unmatched `--exclude` is fine. Left-out entries count as `skipped_by_kind.not_selected`.
- `--strip-components <N>`: drop N leading components; an entry with N or fewer components is skipped (`stripped_away`). `0` and negatives are `InvalidConfiguration`; N above `--max-path-depth` is refused. A hardlink whose target is stripped or unselected is refused as `SecurityViolation` (`sub_code` `LINK_TARGET`); a symlink keeps its target text; a hardlink target containing `..` under any selection is `PathTraversal`.
- `--flatten`: every file lands at the destination top level under its final component; directories are skipped (`stripped_away`); a selected link entry is refused (`SecurityViolation`, `LINK_POLICY`). Same-name files follow the duplicate rule. Conflicts with `--strip-components` (exit `2`).

## Unreachable destination

An `OUTPUT_DIR` that cannot be created, opened or searched (a file where a parent directory should be, no search permission) fails before any entry is written with `IoError`, message `Destination is not accessible: <path>: <step>: <cause>` and the matching `io_kind` (`NotADirectory`, `PermissionDenied`, ...), exit `1`. The path is the one you passed. Fix the path or its permissions; no flag relaxes it.

## `--force`

A regular file is replaced by writing a sibling temp file and renaming over it (like `mv -f`): other hardlinks to the old file keep their content. The destination parent must be writable; a read-only existing file is replaced; owner, ACLs, and xattrs of the old file are not preserved. The new file gets the entry's mode (a ZIP entry without Unix attributes gets `0664`; with no mode at all, `0666 & ~umask`).

Without `--force`, anything already at the landing of a file, link, or hardlink is a conflict, as is a non-directory at the landing of a directory; the check covers implied parent directories and fails before writing with `OutputExists` and the full `error.conflicts` list. `--force` replaces only a file at a file or symlink landing. In place, it refuses before writing: a directory at a non-directory landing and any occupant at a hardlink landing (a hardlink entry never replaces anything) with `OutputExists`, and an existing symlink at a file or hardlink landing, or a symlink with another target at a symlink landing, with `SecurityViolation` (`EXISTING_SYMLINK`). A file or link where the archive needs a directory is refused too. Without `--force` the hint says `Use --force to overwrite.` only when `--force` would replace every one, and otherwise names the paths it does not replace (remove them or choose another destination). `--atomic --force` replaces a whole destination that is not protected (the working directory, a filesystem root, an ancestor of the archive), so it also resolves those paths. Within one archive, a later file or symlink at a path an earlier file or symlink of the same archive wrote is skipped as `duplicate` (without `--force`) or overwrites the file (with); a later hardlink there is skipped as `duplicate` without `--force` and refused under `--force`, with `OutputExists` (`by` `archive`) over an earlier file and `SecurityViolation` (`EXISTING_SYMLINK`) over an earlier symlink, never overwritten and never reported as a corrupt archive; a later file or link at a path the archive made a directory (an explicit entry or an implied parent, e.g. `x/a` then file `x`) fails the run in every mode, `--atomic` and `--force` included (`1 destination file already exists`, under `--force` too: the write phase gives the same `OutputExists` with `conflicts` as the pre-check). Under `--force` an existing symlink with another target is never re-pointed (`SecurityViolation`, `EXISTING_SYMLINK`, `refusing to replace the existing symlink at <entry>`, from the pre-check and the write phase alike); a symlink with the same target is left alone, so re-extracting into the same output succeeds.

## `--atomic`

Extract into a hidden staging directory (`0700`) in the destination's parent and rename into place only on success. Failure discards staging and leaves the destination unchanged (`partial_report.writes` `"rolled_back"`).

- The destination must be missing or an empty directory; a non-empty one fails `OutputExists` with `HINT: Use --force to overwrite.` A symlinked destination is resolved and must be empty.
- With `--force` the existing directory is renamed aside, the new content renamed in, then the old directory removed, so a failure leaves either old or new content. It needs search (execute) permission on the parent, not read. On macOS, a destination whose ACL has a `deny delete` entry for the caller is refused before anything is extracted (`IoError`, `io_kind` `PermissionDenied`, original unchanged).
- `--atomic --force` refuses before extracting (`InvalidConfiguration`, setting `output_path`): `.`, `..`, any directory containing the working directory or the archive, a filesystem root, a file, or a symlink (pass the resolved path). It cannot combine with `--include`, `--exclude`, `--strip-components`, or `--flatten` (`InvalidConfiguration`, setting `entry_selection`); plain `--atomic` can.
- Unix: the published root takes the mode of the destination it replaces or fills (never setuid). With `--force` it also takes the owner as far as the caller may (only root can give a directory away; an unjoinable group drops group bits and setgid). Plain `--atomic` onto an empty directory never takes the uid and takes the group only when the caller owns the destination; a destination owned by someone else also loses group/world write.
- ACLs, onto an existing destination: staged children inherit from the destination's ACL as they would in an in-place extraction, not from the parent's. On Linux and Android the destination's POSIX default ACL is set on the staging directory before extraction, and its full ACL (access and default) is copied onto the root right after the publishing rename. On macOS the destination's inheritable entries are set on the staging directory as `only_inherit` entries (children receive them; the staging directory does not apply them to itself), and the full list is copied onto the root right after the publishing rename. On both, plain `--atomic` onto an empty destination whose ACL denies deleting it is still published (`--force` onto it is refused on macOS, see above), and if that copy fails after the rename the run still succeeds, `root_access_narrowed` reports `acl_copy_failed`, and the root is made `0700` with no ACL where the OS allows. The staging directory's mode stays `0700` throughout. The destination's inheritance is read when staging starts: a later change reaches the published root only. If a destination with inheritable entries vanishes before publish, the root is `0700` with no ACL and `destination_vanished` is reported; a destination with none gets the mode a new directory gets. If the destination is replaced by another directory, the root is `0700` with no ACL and `destination_changed` is reported. Only `--atomic --force` keeps the mode and ACL of a destination without read access (for example mode `0311`); plain `--atomic` onto one fails `IoError` (`io_kind` `PermissionDenied`) naming the destination, since its emptiness cannot be checked, and publishes nothing. With `--force` the root is `0700` with `acl_unreadable` only when its ACL itself cannot be read (for example macOS mode `000` for a non-root caller). If the ACL cannot be copied faithfully the root is `0700`; a named user or group entry that does not map in the process's user namespace also gives `0700` and an `unmapped_id` warning. Every `0700` fallback and every dropped owner, group or write bit is reported as a `root_access_narrowed` warning (reasons in `json-output.md`). Other Unixes and NFSv4 ACLs are not detected.
- ACLs, onto an absent destination: staged children and the published root get what `mkdir` of the destination in the parent would give them. On macOS the parent's inherited entries are captured, cleared from the staging directory and set back as `only_inherit` entries, so the staging directory stays `0700` with no applicable entry during the run, and the captured list is copied onto the root right after the publishing rename. On Linux the parent's default ACL stays on the staging directory (the mode's group bits mask it).
- Plain `--atomic` onto an empty directory owned by someone else: staged children inherit that owner's entries, as in place, and the root stays `0700` with an `ownership_differs` warning when it carries an ACL.
- Unix: a rollback removes the staged content through a descriptor on the staging directory, at any depth. A directory replaced while the removal is under way is not removed, and the private staging directory is named in `leftover_path`.
- macOS only: a rollback also removes the run's own staged entries that inherited a `deny delete` entry. Left in place, with the private staging directory named in `leftover_path`: an entry the caller may not open (no read, write or search), one with a link from outside the stage, one carrying an ACL entry that was not inherited, and one the run did not create. A rollback after the root's permissions were adopted (a failed publishing rename) sweeps only while the staged root is still owned by the caller, not group- or world-writable, and carries only `only_inherit` ACL entries; otherwise nothing is swept.
- Unix: staging needs a filesystem that reports the owner and mode bits a new directory was created with. Where it does not (some network and Windows-backed mounts), `--atomic` fails before extracting (`IoError`); the empty staging directory is removed, or named in `leftover_path` when it cannot be.
- Windows: the staging directory is owner-only (protected DACL granting only the current user) while the run lasts. After the publishing rename the root and every entry below it are rewritten, the root last, to what a new directory there would get: for an absent destination the inheritable entries of its parent, for `--atomic --force` the DACL of the destination it replaces. A DACL that cannot be read gives `acl_unreadable`, a destination replaced meanwhile `destination_changed`; in both cases, as for a parent with no inheritable entries or a failed rewrite (`acl_copy_failed`), the root stays owner-only. When the rewrite fails partway, entries already rewritten keep their final DACL. Reparse points are never followed. Plain `--atomic` onto an existing empty directory fails `OutputExists`.
- A failed publishing rename of plain `--atomic` (for example `OutputExists` because the destination was filled meanwhile) keeps its cause as `error.kind` and reports the extraction counts in `partial_report` with `writes` `"rolled_back"`.
- A failed swap is an `IoError` whose message says whether the destination is unchanged or restored and where a backup is left; it reports the extraction counts in `partial_report` with `writes` `"rolled_back"` (the discarded run), which does not mean the destination is intact after a failed restore. `leftover_path` names a staging directory the swap could not remove.
- Plain (non-atomic) `extract` resolves a symlinked destination via `canonicalize()` and writes through it, like `tar -C`.

## Download mark (`--mark-propagation`)

Archives downloaded from the internet carry a mark (macOS `com.apple.quarantine` attribute, Windows `Zone.Identifier` stream) that Gatekeeper, SmartScreen and Office Protected View read per file. By default extraction drops it (`never`: the archive's mark is not read). With `when-marked`:

- The mark of the archive file is read once and copied onto every extracted file, hardlink copies and `--force` replacements included; on macOS also onto every directory this run creates (never a pre-existing directory, the destination root or the `--atomic` staging root). Symlinks are never marked.
- macOS: a fresh `com.apple.quarantine` value per object (new identifier, agent `exarch`, source timestamp, flags limited to download/sandbox/hard bits). Windows: a `Zone.Identifier` stream holding only the source `ZoneId` (0-4; no URLs). Linux and other Unix: nothing is copied and the outcome is `unsupported_platform`.
- The mark is written before an entry's final read-only mode applies (a `0444` entry is marked and ends `0444`). A failed write is counted in `failed` and extraction continues (exit `0`); text output then adds a warning line. Marks never come from archive content: a TAR `com.apple.quarantine` PAX record is ignored.
- Windows: an archive file on a volume that does not support named streams (FAT, exFAT; network shares are unverified) is `unmarked`, not `unreadable`; a failing volume query still falls through to the stream read.
- A source mark that exists but is malformed, non-ASCII or too long (macOS value over 256 bytes; Windows stream content past 4096 bytes is ignored) is still a mark: macOS writes flags `0001`, Windows writes `ZoneId=3` when no valid `ZoneId` is in the first 4096 bytes. Only an I/O error while reading the mark gives `unreadable`, marks nothing and prints the warning line; an unmarked archive gives `unmarked`.
- Text output prints `Download mark: copied to N items, M failed` (or the reason nothing was copied) when the flag is `when-marked`; `--json` always carries `mark_propagation` (see [json-output.md](json-output.md)).
- A destination volume without extended attributes or streams (FAT; network shares are unverified) makes every write fail: `failed` counts them.

## `--decode-reuse` cost

`off` decodes every entry twice, `memory` keeps decoded output in RAM, `temp-file` keeps it in an unnamed file in `TMPDIR`. On a tmpfs or ramfs (Linux, FreeBSD, macOS tmpfs mount) `temp-file` is charged to the decoder memory limit like `memory`. A macOS `hdiutil` RAM disk is not detected, so a `TMPDIR` there holds the spool in memory outside that limit. Prefer `memory`; use `temp-file` only to keep RSS low.

Measured on Linux (Linux VM (Docker Desktop), aarch64, 12 CPUs, release CLI, deflate ZIPs of 10 MiB members at ratio about 2.2, `hyperfine --warmup 2 --runs 10`, mean wall time; `TMPDIR` on an ext4 Docker volume or a `--tmpfs` mount, output on a volume). This is a VM, not a bare-metal host. Each `TMPDIR` was a separate hyperfine run, so `off` and `memory` differ between rows by run noise.

| Decoded | `TMPDIR` | `off` | `memory` | `temp-file` | `temp-file` / `memory` |
|---------|----------|-------|----------|-------------|------------------------|
| 100 MiB (48 MB ZIP) | ext4 | 283 ms | 176 ms | 226 ms | 1.3x |
| 100 MiB | tmpfs | 331 ms | 174 ms | 208 ms | 1.2x |
| 300 MiB (146 MB ZIP) | ext4 | 818 ms | 525 ms | 1009 ms | 1.9x |
| 300 MiB | tmpfs | 801 ms | 545 ms | 608 ms | 1.1x |

The 300 MiB ext4 `temp-file` cell is dominated by writeback outliers (standard deviation 539 ms, minimum 590 ms, median 748 ms, maximum 1842 ms): 1.1x at the minimum, 1.4x at the median. The `off` runs at 100 MiB on tmpfs and 300 MiB on ext4 are also noisy (standard deviation 80 ms and 50 ms). Peak RSS is 5.5 MiB for `off`, 5.6 MiB for `temp-file`, 106 MiB and 256 MiB for `memory` (the 256 MiB limit means the tail of the 300 MiB archive is decoded twice in both keeping modes).

## Pre-flight listing and partial extraction

Non-atomic extract into an existing destination first lists the archive (same quotas) to detect conflicts and size the progress bar. Quota violations there fail with a plain error and **no** `partial_report`; only checks needing the real destination (symlink/hardlink escape) can leave a partial extraction.

The list pass is skipped for a TAR extracted with `--atomic`, or into a not-yet-existing destination whose parent exists. Such runs are atomic: any refusal leaves nothing on disk and reports `writes: "rolled_back"`; staging can grow up to `--max-total-size`. For an existing destination, a gz/bz2/xz TAR decoding to at most 256 MiB is decoded once (the list pass spools to an unnamed temp file in `TMPDIR`); otherwise it is decoded twice.

## Cancellation

`extract` and `create` turn SIGINT and SIGTERM into a cancelled run (SIGHUP keeps its default so `nohup` works; no handling on WASI; on Unix a SIGINT or SIGTERM inherited as ignored, e.g. under `trap "" INT`, is left ignored and never cancels the run). The first signal stops the run, core discards the `.exarch-XXXXXX` staging entry, and the process re-raises the signal: a signal death, shell status `130` (SIGINT) or `143` (SIGTERM), `error.kind` `Cancelled`, message `Operation cancelled`, `partial_report.writes` `"rolled_back"` once entries were written. `--atomic` and `create` leave the destination or previous archive as it was; an in-place `extract` keeps written entries (`"kept"`). The stop is noticed at entry boundaries, inside a large entry's copy, and per entry during the listing pass.

A second signal ends the process at once by the first signal and, in text mode, prints what may remain: a `.exarch-*` temp file (`create`), a `.exarch-*` staging directory (`extract --atomic`), or the written entries (in-place `extract`), each in the directory core stages in (the canonical parent of the destination, so a destination spelled `a/b/..` or reached through a symlink names the real directory). Only `extract --atomic --force` mentions the `.exarch-backup-*` entry, which is the original destination: if the destination is missing, rename it back to the resolved path the hint names instead of deleting it. Under `--json` the forced exit prints one `Cancelled` error document. A stop after the last poll lets the run finish, report, then die by the signal. Windows has no signal death and exits `130`. `list`, `verify`, and `completion` install no handler.
